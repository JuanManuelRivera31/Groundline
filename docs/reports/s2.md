## Configuration chosen and why

- **Best hybrid by the agreed rule** (section R@8, then MRR, then document level): **C, k=60, c=10+10, N=8**. It ties D on R@8 and wins on MRR.
- **Recommended default for S3: vector-only (c=20, N=8).**
  - It beats every hybrid configuration at section level.
  - The R@8 gap is one question (within noise), but the R@1 and MRR gap is large: 75.6% vs 48.9% at R@1, which is 12 questions.
  - Hybrid only wins on document R@8: 100% vs 97.8%, one question.
- **Diagnosis:** with equal-weight RRF, a chunk that appears in both lists at middle ranks (e.g. vector 2 / fts 1) outranks the correct vector #1, which full-text ranks low or misses.
  - On dev, hybrid lost 14 vector top-1 hits and gained 2.
  - Full-text alone is weak: OR semantics plus `ts_rank_cd` favour long chunks that match generic words.
  - Changing k (60 → 20) had no effect at these cut-offs. Fewer candidates helped a little.

## Decisions taken autonomously

- **Doc→topic map** for stratification: `evals/plausible/topics.json`. Four support-irrelevant docs are excluded.
- **Validation:** the vendor's documented support address (`@plausible.io`) is allowed in the email check (approved).
- **Grouping:** questions that share a source chunk are grouped only within the same expected behavior (approved).
- **Dev v2 extension:** done with a write-once script (`pnpm eval:extend-dev`) that refuses to run twice and checks the test hash.
- **Threshold view** added to every run: answer median/p10, abstain median/p90, answer questions below the abstain p90.
- **Run files:** if a file with the same name exists, a numeric suffix is added, so runs never overwrite each other.
- **Recommendation:** vector-only for S3, even though the session's target was hybrid. This is grounded in the dev numbers above.

## Proposals (not applied; the chunker and fusion were out of scope for tuning)

1. **Deduplicate results by URL** before taking the top N. Long sections split into several chunks share an anchor (dev-030 shows a duplicate in the top 3), which wastes context slots.
2. **Weighted fusion or full-text as a fallback**: e.g. RRF with weight 0.3 on full-text, or using full-text only when max cosine is low. Both would need a fresh dev comparison.
3. **Better full-text query**: phrase or AND-first with OR fallback, and a corpus-specific stopword for "plausible". This should make FTS useful for exact product terms.
4. **Chunker:** no change proposed. Document-level R@8 is 97.8–100%, and most misses are near-section confusions within the right page.

## Risks and open questions

- **LLM-written questions** may be cleaner than real traffic. Typos were included: ~10–15% of answerable candidates, ~8% of unanswerable ones. The owner audit sample is pending.
- **Mixed injections:** two prompt-injection questions wrap a legitimate question. The approved grading is to refuse the injection and answer the legitimate part, and S3 must grade that.
